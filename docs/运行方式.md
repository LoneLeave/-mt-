# mtbot 运行方式（2026-11-10 更新）

## 手动跑一轮（推荐）
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File logs\_start_round.ps1 -Tasks "all" -Tag fullNN -Boot
```
- `-Tasks all` → `--profile all`（39 个任务）；也可 `-Tasks "bounty,tower"` 只跑指定任务。
- `-Boot` → 传 `--boot`（模拟器停在桌面/上一轮残留在战斗页时自己拉回来）。**建议总是带上**。
- 默认带 `--oas-stop`（阴阳师抢前台就直接 force-stop 它，见 `mtbot/oasguard.py`）；`-NoOas` 关掉。
- 日志：`logs\_<Tag>_<yyyyMMdd_HHmmss>.log`；路径同时写进 `logs\_<Tag>_last.txt`；启动记录写 `logs\_start_round.log`。
- 为什么不用 `schtasks /SC ONCE /ST 23:59`：那种一次性任务会在 23:59 集体触发、用 `>` 重开同一个日志把结果截断（2026-11-10 踩过，run21~31 日志被清空）。

## 自动每天跑（已配置，2026-11-10 起）
```
mtbot_daily_0005   每天 00:05   logs\_start_round.ps1 -Tasks all -Tag daily0005 -Boot
mtbot_daily_1205   每天 12:05   logs\_start_round.ps1 -Tasks all -Tag daily1205 -Boot
```
- 00:05 那次是当天重置后跑完整一轮（塔/传奇/邪能/罪魂/角斗场/荣耀/公会试炼/圣兽次数都恢复）。
- 12:05 那次是公会圣兽 12:00 开放后补跑一轮（顺带把上午新解锁的领取做掉）。
- 两个任务互不冲突：`logs\_<Tag>_<ts>.log` 带时间戳不会互相截断；真重复启动时 `mtbot/run.py` 的单实例锁会拦住（日志写「已经有一个 mtbot 在跑」）。
- 查看/停用：`schtasks /Query /TN mtbot_daily_0005 /FO LIST`、`schtasks /Change /TN mtbot_daily_0005 /DISABLE`。

## 看结果
```powershell
& D:\anaconda\python.exe -X utf8 logs\_audit_log2.py logs\_<Tag>_<ts>.log     # 一行汇总 + 耗时榜 + hits=0 清单
& D:\anaconda\python.exe -X utf8 logs\_make_report.py                        # 生成 docs\最近一轮结果.md
& D:\anaconda\python.exe -X utf8 logs\_daily_digest.py 6                     # 最近 6 轮的 o/X/s 序列 + 连续 0 进展清单
& D:\anaconda\python.exe -X utf8 logs\_idle_scan.py logs\_<Tag>_<ts>.log     # 空转（>6s 间隔）按任务汇总
```

## 钻石规则（用户 2026-11-10）
- 只允许：`attempt`（买挑战次数）、`gacha`（抽奖）、`bounty_refresh`（悬赏刷新，用户单独授权）。
- 实现：`mtbot/config.py::RuntimeConfig.diamond_kinds` + `mtbot/tasks/base.py::may_spend(..., kind=...)`。
- 其余花钻入口（快速挂机次数、付费扫荡、商店钻石刷新、铁匠铺/战令付费按钮、商人议价确认）全部不点。
