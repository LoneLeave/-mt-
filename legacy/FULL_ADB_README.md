# full_adb.py — 奖励领取 / 属性提升 / 战斗 一体化脚本

`daily_adb.py` 只覆盖每日任务；`full_adb.py` 覆盖其余所有「红点」界面：邮件、军衔、好友、福利、
达标返利、勇者计划、圣物、升星、铁匠铺、共鸣、争霸赛，以及历练里的塔 / 传奇试炼 / 邪能神殿、
角斗场、荣耀竞技场。

## 运行

```bash
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\full_adb.py --list
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\full_adb.py --dry-run
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\full_adb.py --profile light
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\full_adb.py --profile daily
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\full_adb.py --profile full
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\full_adb.py --only relic,star,equipment
```

- `light`：只领免费奖励 + 一键提升（不打架）。
- `daily`：日常任务一键版（快速挂机 / 强化 / 商店刷新 / 公会捐献 / 公会试炼 / 悬赏 /
  主线战役 / 日常领奖+活跃箱）。2026-10-29 逐项实测过，取代旧的 `daily_adb.py`。
- `full`：light + 战斗（塔 3 层、传奇试炼 3 次、邪能神殿扫荡、角斗场、荣耀竞技场）。
- `all`：full + 抽卡（千抽福利、召唤免费单抽、打造免费单抽）——**会消耗钻石/券/锤子**，默认不跑。
- `--skip tower,colosseum` 排除模块。

## 可重复运行是怎么保证的

1. **按钮全部用 200ms 长按**（`input swipe x y x y 200`）。本作里 50ms 的 `input tap` 经常不触发，
   这是之前「点了没反应」的主要原因。
2. **动手前先看颜色**：
   - 亮金色（R≥212、R−B≥85）= 可领取 / 可挑战 / 可升级；浅土黄的「前往」和绿色的「已领取」都会被跳过。
   - 红点角标（橙红色像素簇）用于判断免费抽卡次数。
   - 复选框（跳过战斗）已勾选时不再点，避免把勾去掉。
3. **每个模块独立 try/except**，失败后 `ensure_main_city()` 回主城继续。
4. **回主城用「返回键 → 确认退出弹窗」判定根节点**：主城按返回才会弹「确认要退出游戏吗？」，
   看到它就取消并认为已到主城，比识别截图背景可靠。
5. **次数用尽自动停**：角斗场点「挑战」后对比前后截图，画面没变化就是「挑战次数不足」，立刻停；
   塔/试炼只看挑战按钮是否亮金，灰了就停。
6. **不碰任何人民币入口**：每日特惠、三日直升、超值首充、限时/连续累充、终身福利的充值档位都不点。

# boot.py — 从零启动（模拟器 → 游戏 → 进主城）

```bash
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\boot.py
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\boot.py --cold
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\boot.py --then light
C:\Users\123\.conda\envs\Reas\python.exe -I E:\Reverse\auto_script\boot.py --cold --then full
```

- `--cold`：先 `am force-stop` 再启动，等于真正冷启动（实测 44–47 秒进主城）。
- `--then light|full|all|daily`：进主城后接着跑 `full_adb.py` 或 `daily_adb.py`。
- 模拟器已经开着就复用；没开则 `MuMuManager control -v 0 launch` 并等 `sys.boot_completed=1`。
- 已经在主城且没加 `--cold` 时直接跳过启动（幂等）。

## 登录流程（实测）

1. `AgreementSplashActivity` → 「资源加载中」splash
2. 公告弹窗（底部有协议勾选，已勾选）→ 点空白关闭
3. 标题页：确认勾选《用户协议》→ 点「开始游戏」(360,1040)
4. 「冒险即将开始」加载
5. 登录后弹窗链：离线收益（点「领取收益」）→ 挂机收益 → 深海秘宝 → 累充30元 → 全屏贵族/VIP 活动页（用左下返回箭头退出）…
6. 主城

## 两个关键实现细节

- **红点关闭按钮要偏移点**：右上角红色圆形 X 的实际命中点在图标**左下约 (-20, +10)**。
  `boot.py` 用像素聚类在截图里找红色圆钮，再按偏移组合去点，避免写死坐标。
- **全屏活动页不是弹窗**：它没有压暗遮罩，点空白无效，要用左下返回箭头 (88,1215) 退出；
  而 Android 返回键会直接弹「确认要退出游戏吗」，所以脚本只用返回箭头。

## 注意：模拟器和阴阳师脚本共用

同一台 MuMu 上跑着 OnmyojiAutoScript（`com.netease.onmyoji...`），它会抢占前台并把模拟器转成横屏。
`boot.py` 每轮都检查前台包名和截图方向，被抢走就重新 `am start` 拉回本游戏。
如果两边同时跑，操作会互相打断——建议跑本脚本前先把 OAS 停下来。
